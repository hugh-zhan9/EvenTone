## 2026-09-17 · 授权后实机回归

用户确认已允许 EvenTone 系统音频录制。使用同一路径的应用验证，未代操作系统权限，也未重启音频服务、修改默认输出或硬件音量。测试过程中界面先后观察到「还得是原道」48 kHz 和「外置耳机」44.1 kHz；以下成功电平验证针对后者，不据此声称两个设备均完成验证。

### 修复与基线

授权前，HAL 曾出现 30 秒级等待、没有回调；此前已将所有 HAL 操作移至独立串行队列。授权后，初始化/清理等待缩短，外置耳机通路可接收合成参考音。仍发现设备重建后无回调超过 5 秒时，被应用自己的 watchdog 关闭。无回调不够证明 HAL 故障，因此删除这条自动关闭规则：通路成功开启后，空闲保持等待；实际 Core Audio 错误和缓冲格式错误仍报告并清理。

保留回调新鲜度仅供界面使用：超过 0.5 秒无新回调时隐藏过期电平，不把最后一个电平当作仍在播放。修复前 AppModel 保存在 `.build/baseline-20260917/AppModel.swift` 供本轮差异检查；该临时目录不作为长期交付依赖。

### 最终构建的实际观察

整体音量为 80%，设备补偿 0 dB；参考声是本地生成的 440 Hz 立体声正弦，48 kHz PCM，未录制用户音频。电平由应用的实际 Core Audio IO 回调计算并通过原生 UI 读取。

| 检查 | 观察结果 |
| --- | --- |
| 开启后无内容等待 12 秒 | 总开关保持开启，显示「已启动 · 等待音频」，未误关闭 |
| 随后播放较轻参考声 | 自动恢复「正在处理音频」；输入 -30.9 dBFS，自动增益 +9.0 dB，输出 -23.9 dBFS |
| 播放较响参考声 | 输入 -21.4 dBFS，自动增益 -0.6 dB，输出 -23.9 dBFS |
| 关闭自动均衡，再播放较轻参考声 | 输入 -30.9 dBFS，输出 -32.8 dBFS，符合 80% 音量的约 -1.94 dB 衰减 |
| 当前设备补偿改为 -3 dB | 输出 -35.9 dBFS，相对未补偿下降约 3 dB |
| 关闭总开关 | 界面变为已关闭；AudioDeviceStop 与 DestroyIOProcID 返回 0，未显示清理错误 |

上述验证证明数字音频捕获与处理通路工作，不等同于测量耳内声压或确认主观听感。测试结束恢复补偿 0 dB、自动均衡开启、整体音量 80%、总开关关闭。

修改后再次运行 `./scripts/test.sh`，11 / 11 通过；`./scripts/build.sh` 构建、打包与签名校验通过。独立只读复审本次 AppModel / ControlView 差异未发现新增 Critical / Important。本次空闲缺陷通过上表实机回归验证，未用镜像实现的单元测试替代 HAL 实际行为。

### 重复实机检查

1. 开启应用并等待超过 5 秒；应保持等待，不能自动报错关闭。
2. 播放两段不同音量的参考内容；稳定后比较输出电平，再关闭均衡比较差异。
3. 固定内容与整体音量，将设备补偿降低 3 dB，观察输出相应降低；最后恢复设置。
4. 关闭总开关，检查无清理错误及后续正常播放；主观恢复原声仍可配合试听确认。
