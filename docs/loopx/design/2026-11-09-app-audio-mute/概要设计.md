# EvenTone 应用声音管理

状态：2026-11-09 用户已授权实现，明确关闭总开关解除静音、不记住选择。技术方案由实现者在原模块边界内确定，已完成工作区实现与自动化检查，2026-11-10 授权后完成 Chrome/Edge 及外置耳机/显示器输出验证；内置扬声器缓冲格式问题已修复，三种输出的同组静音验收通过；睡眠恢复未实测。基线 main d22b966；任务分支 feature/app-audio-mute。详细合同见[需求设计文档](需求设计文档.md)。

## 目标与边界

在当前输出设备上列出应用音频来源，单独静音／恢复一个浏览器的全部音频，其他应用继续均衡播放。不暂停视频，不读取网页或麦克风。按应用而非标签页控制；不新增每应用音量滑块。沿用 macOS 14.2+ 和既有输出格式限制。

<a id="D-001"></a>
## D-001 · 声音来源与通路

Behavior / Interface Contract，来源：用户的多个浏览器同时播放场景；状态：实施选择。

架构（箭头为调用关系）：

```text
ControlView → AppModel → AudioWorker（原串行队列）
                           ├→ AudioApplications（枚举与应用归并）
                           ├→ ApplicationMuteState（仅内存选择）
                           └→ AudioRouter（拥有两类私有 tap）→ 原 AudioDSP
```

原 AudioRouter 是全局混音后的处理点，不能在 DSP 中区分应用。扩展它拥有一个按进程静音的 tap；原均衡 tap 排除该组进程和自身，其他声音沿用原 DSP。选择改变时原地更新 tap description，避免重启整个输出设备。原始输出抑制和混音排除必须一起成功，不能只排除而放行原声。失败走现有显式错误与通路清理，不宣称静音成功。

应用身份优先取可执行路径最外层 app 包，将 Chrome 等内嵌 helper 合并；独立音频进程按自身身份显示，不凭名称前缀把共享 WebKit 进程猜成 Safari。当前设备上的音频输出活动只表示系统输出流运行，不声称检测到人耳可听声音。

<a id="D-002"></a>
## D-002 · 生命周期

Behavior Contract，来源：本轮两个用户回答；状态：已确认。

| 事件 | 处理 |
| --- | --- |
| 开启总开关 | 沿用原启动；新运行无静音选择 |
| 静音／恢复应用 | 成功后更新界面，其他应用选择保持 |
| 应用暂停、进程更换 | 保留本次运行的应用选择，动态更新进程组；无进程时仍能解除选择 |
| 切换设备、睡眠重建 | 释放旧设备资源，保留本次会话选择，在恢复通路时应用 |
| 关闭总开关、通路失败 | 释放全部 tap，清空选择；失败显示清理错误 |
| 退出 | 原退出清理加静音 tap 清理，系统回收私有对象；无静音持久化 |

进程发现每秒刷新，不承诺新音频进程启动瞬间零帧泄漏。列表读取不建立 tap；仅总开关开启时可更改静音。不会修改现有 Preferences 的总开关持久化规则。

## 验证与风险

原有 30 项测试作为基线；新增进程归并、空列表、选择保留、关闭清空和失败不提交选择的可重复测试。实机验证两个独立声源、静音与恢复、关闭解除以及原均衡输出；浏览器 helper 归属、Core Audio 多 tap 行为、睡眠及设备变更需要真实环境检查。实现不得把静态检查写成实机通过。

现有依据：Sources/EvenTone/{AudioRouter,AudioHardware,AppModel,Preferences,ControlView}.swift；Apple Core Audio CATapDescription 与本机 SDK AudioHardware.h（kAudioTapPropertyDescription 可修改）。Support lenses: none。设计走查覆盖开启、静音、错误清理、关闭与设备重建；纯文本架构无需渲染器。
