# EvenTone（匀声）MVP

2026-09-16。来源：本轮用户描述 AirPods / 外置耳机音量不一致、不同视频音量不一致，并确认「设备校准 + 实时响度均衡」方向，授权命名、创建目录并实现 demo MVP。名称由实现者选择；不表示商标可用性结论。

## 目标与边界

AC-1：菜单栏应用显示当前系统默认输出设备，并按设备 UID 保存独立补偿，设备切换后自动应用。
AC-2：实时平滑调节内容音量；抬升较轻内容、降低较响内容；静音不抬升底噪，限制最大增益和数字峰值。
AC-3：提供总开关、自动均衡开关、整体音量、设备校准；退出后释放音频资源，系统继续正常播放。
AC-4：本地处理，不保存、上传或记录音频，不访问麦克风内容。需要 macOS 原生系统音频权限。

本版校准由用户播放同一参考片段、主观调节补偿完成；不声称测量耳内声压。MVP 使用短时 RMS 估计，不声称通过 LUFS / EBU R128 认证。首先支持当前默认输出设备的单声道 / 立体声 Float32 音频；多声道、独占输出、受保护内容和 Bluetooth 通话模式需要单独验证。菜单栏小，不意味着音频兼容性无需验证。

<a id="D-001"></a>
## D-001 · 本地音频通路（实施选择；承接已批准方向）

架构与数据流：`SwiftUI 控制界面 → AppModel（状态、设备配置） → AudioRouter（Core Audio 资源） → AudioDSP（实时处理） → 当前物理输出设备`。系统其他进程的音频通过 scoped process tap 进入 AudioDSP；AppModel 的 UserDefaults 只保存设置。AudioDSP 不访问文件、网络或日志。

使用 macOS 14.2+ Core Audio process tap 和私有 aggregate device，避开额外安装驱动。tap 排除自身，只在实际读取时静音原信号；处理后输出到相同设备，避免双重播放和反馈。仅在用户选择输出设备时更改系统默认输出，不自动抬高硬件音量。音量键保留系统语义；应用整体音量是额外衰减。

<a id="D-002"></a>
## D-002 · 校准与均衡（实施选择；AC-1 / AC-2）

设备补偿按稳定 UID 保存，首次设备为 0 dB。默认自动均衡开启，首次运行总开关关闭，由用户开始。增益平滑变化，左右声道使用相同增益以保留声像；尾部限幅防止数字削波，但不保证真实声压安全或无采样间峰值。暂停和切换设备重建分析历史，避免前一设备或内容的历史增益造成突增。

<a id="D-003"></a>
## D-003 · 生命周期（实施选择；AC-3 / AC-4）

| 当前状态 | 事件 | 结果 |
| --- | --- | --- |
| 已关闭 / 错误 | 用户开启 | 建立 tap、aggregate、IOProc；成功进入处理中，失败释放已创建资源并显示原因 |
| 处理中 | 关闭 / 退出 / 睡眠 | 串行队列停止 IOProc、释放 aggregate 和 tap；退出时由系统回收进程私有资源 |
| 处理中 | 默认设备或格式改变 | 停止旧通路，按新设备配置重建；失败显示错误并停止，不静默重试 |
| 睡眠暂停 | 唤醒 | 若睡前开启，按当前设备重建 |
| 处理中 | 参数改变 | 原子发布参数，回调内平滑应用 |

连接和清理过程中显示进行中状态；退出按钮不等待 HAL。格式指纹包含编码、位宽、布局，不能只比较采样率与声道数。错误不能伪装成正在均衡。无音频只显示等待信号，不能据此判断已获权限或内容可捕获。2026-09-17 实机修订：无回调时不按固定秒数销毁通路；设备空闲可能暂停 IO，待后续音频恢复。回调新鲜度仅用于隐藏过期电平。关闭均衡但保留总开关时仍执行设备补偿、整体音量和限幅。

<a id="D-004"></a>
## D-004 · 快速切换输出设备（2026-09-17 用户新增要求）

菜单列出当前可作为默认输出的已连接设备，排除 EvenTone 自己的处理设备；按 UID 识别，不按名称或列表位置绑定。设备增减时更新列表。选中设备先停止旧音频通路，在既有 AudioWorker 串行队列设置系统默认输出；只有属性读回确认新设备后才加载它的补偿并按原总开关状态恢复处理。总开关关闭时也能切换设备。

设备在点击前断开：明确报错，不把旧列表当作有效设备；设置失败或设置调用返回后 5 秒内未确认：显示错误、停止本应用处理，不宣称成功、不自动切回另一设备。操作期间禁用重复切换。未连接的蓝牙设备需先通过 macOS 连接；MVP 不管理蓝牙配对。系统提示音的独立输出设置不在此修改范围。

<a id="D-005"></a>
## D-005 · 登录时启动（2026-09-17 用户新增要求）

使用 macOS 13+ 原生 SMAppService.mainApp 注册/取消登录项，不新增 LaunchAgent、后台服务或密码权限。系统 ServiceManagement 是唯一状态来源；应用重开、重新成为活动应用或打开控制面板时刷新。已注册且获准、待系统允许、未注册、服务不可用分别显示，失败不伪装为开启。

菜单提供「登录时启动」开关；macOS 要求额外允许时显示原因和系统设置入口。登录启动与音频总开关独立，启动后的处理状态遵循 D-006。注册的是当前 .app 路径，移动应用后需在新位置重新确认登录项。不会为了验证而注销或重启用户会话。

<a id="D-006"></a>
## D-006 · 恢复总开关（2026-09-17 用户明确修改）

用户要求启动时保持上次退出前的总开关状态：开启则在设备检测成功后自动建立处理通路，关闭则保持关闭；手动打开和登录启动使用相同规则。首次运行或升级后没有保存值时仍默认关闭。复用 Preferences 的 UserDefaults 保存，不新增存储或启动流程。

总开关变化立即保存，退出时释放资源不改变保存值。睡眠和设备重建不改变开启意图；运行故障导致总开关关闭时保存关闭，不在本次运行或下次启动自动重试失败通路。系统仍负责检查音频权限，不保存虚假的授权标记、不跳过系统授权。这条用户裁定替代先前“每次启动默认关闭”的规则。

## 验证与交付

<a id="D-008"></a>
### D-008 · 引导校准（2026-09-17 用户新增并明确保留手动补偿）

交互修正（同日用户反馈）：取消必须返回主页面。主窗口和菜单栏共用 AppModel 的校准状态决定面板内容，不再各自维护 sheet 的显示开关。校准页分阶段展示选择、试听、反馈与保存，顶部保留“取消并返回”；取消和保存沿用原处理恢复流程。窗口/菜单栏面板消失时丢弃未保存校准。手动补偿保持原有入口与行为。

新增独立引导入口，原设备补偿滑块、重置和按 UID 记忆完整保留。当前默认设备作为参考，用户选择另一已连接的输出设备；试听相同参考声，以“目标更响 / 目标更轻 / 差不多”判断。初次调整 2 dB，判断方向反转时减半，最小 0.5 dB，保持已有 -12…+12 dB 范围。到达范围上限明确提示，不声称完成匹配。

CalibrationSession 只持有本轮草稿，复用 Preferences 保存目标 UID 的补偿。只有双方都试听过且点击“听起来一致，保存并返回”才写入目标补偿；参考及其他设备不变。取消、关闭引导、退出均丢弃草稿；保存后可继续手动微调。共用同一物理接口而无独立 UID 的两副耳机不能自动区分，本版要求两个不同 UID，各自试听时可用即可。

AudioWorker 继续拥有音频资源及串行操作，新增内存参考声播放器（AVAudioPlayer.currentDevice 按 UID 路由），无需另建捕获通路，不读麦克风、不写音频文件。参考声为固定种子的柔和噪声，每次 6 秒，起止淡入淡出；使用相同整体音量、参考设备已保存补偿和目标草稿补偿，自动均衡不参与参考声。数值峰值固定受限，不声称测量真实声压。

普通处理保持（用户同日要求进入校准时也保持补偿）：进入和取消不停止或重启普通处理；已开启时整体音量、设备补偿、自动均衡及其当前增益继续生效，原先关闭则不代为开启。现有 CATapDescription 排除本进程，参考声由同进程 AVAudioPlayer 按 UID 输出，只使用会话冻结的整体音量与补偿一次，不经过普通 DSP。AudioWorker 继续串行拥有两种资源，普通通路启停只操作 AudioRouter，试听启停只操作 ReferencePlayer；退出释放两者。无需新队列、捕获通路或后台服务。

普通处理继续跟随系统默认设备和格式变化，校准保存独立的参考 UID、名称、补偿快照，不能随主界面设备更新而改变。普通处理的真实硬件故障仍关闭并报告，但不丢弃校准草稿；试听失败仅停止试听并允许重试。睡眠结束校准并停止普通处理，唤醒按保存意图恢复。保存目标补偿时，若目标恰为当前普通输出，原地更新其 DSP 配置，不重启音频通路。引导期间普通控制仍锁定以固定比较基准。要求用户暂停其他内容、保持系统音量不变，避免日常声音与参考声叠加影响听感；应用不代用户暂停其他软件。

连接检查时机（同日用户明确要求）：只在播放时检查本次试听设备，不在进入、选择、后台设备通知或保存时要求两副设备同时在线。进入仍需有当前参考设备和非零整体音量，但不要求第二副设备已连接；设备列表随通知更新，已选 UID 和草稿保留。ReferencePlayer 复用现有按 UID 查询及播放路由检查，失败显示可重试错误，只清除本次失败一侧的试听完成标记，不作永久失效。保存仍需双方试听完成，写入选定 UID；不读取连接状态作为保存条件。后台刷新设备列表并维护当前默认输出的普通处理，不对校准参考的历史格式作一致性检查。睡眠取消本轮校准，播放中的路由偏移仍停止声音，不自动改播其他设备。普通处理启停与故障遵循上文“普通处理保持”的规则。

此前试听误判修正发现：失败会话参考为“外置耳机”，当前默认输出为“还得是原道”，两者同时出现在设备列表。校准按明确 UID 路由，系统默认输出变化不影响指定目标，因此已去掉默认输出一致性限制。本次按用户要求进一步将连接检查收敛到播放路径，删除会话的双设备及参考格式检查；不新增设备状态存储或系统输出写入。

<a id="D-007"></a>
### D-007 · 自动构建与 GitHub Releases（2026-09-17）

来源：用户要求提交后通过 GitHub Actions 打包发布。沿用现有测试与构建脚本，首次支持已验证的 Apple Silicon（arm64）、macOS 14.2+。main 推送生成以提交 SHA 标识的预览版；vX.Y.Z 标签发布正式版，标签必须与 Info.plist 版本一致。PR 只测试和构建，不发布。手动运行只构建，不产生额外发布。

构建 job 只读仓库、执行测试和编译、验证签名并生成 ZIP 与 SHA-256 校验文件，保存为 Actions artifact。独立发布 job 只在允许的 push 事件成功构建后获得 contents:write，下载本次运行的产物，使用 GitHub CLI 发布到精确提交。动作固定到已核实的提交 SHA；不使用个人令牌、不接收不可信事件字符串作为 shell 代码。

同一发布标签串行执行；已存在发布时明确失败，不覆盖文件或移动标签。发布前将远端轻量或注解标签解引用到提交，必须等于本次构建 SHA；缺失的预览标签显式创建后读回，缺失正式标签直接失败。GitHub CLI 显式创建草稿并上传文件；上传完成再核对标签，成功后才公开。失败检查日志及可能残留的草稿，不自动重试。预览版不标记为 Latest。构建复用临时签名，说明未做 Developer ID 公证，不改变本机运行应用或现有授权。

用户已明确选择 Releases + Actions 构建产物，以及 main 预览版 / v* 标签正式版；不增加 Packages / OCI 发布。

新建目录，无旧实现和测试基线。验证包括 DSP 合成音频回归、设备配置持久化、原生构建、打包及签名检查、菜单栏启动检查。实际 AirPods / 外置耳机听感、权限交互、受保护内容、长时间播放与音画同步须明确区分实测和待测。

详细字段、测试对应和执行结果见 [需求设计文档](需求设计文档.md)。本设计用文字数据流和状态表表达，无待渲染图。未新增账号、服务或外部数据边界；Support lenses: none。
