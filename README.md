# EvenTone · 匀声

EvenTone 是一个原生 macOS 菜单栏工具，用来减少切换耳机、切换视频时反复调音量的麻烦。

不同耳机可以分别记住合适的音量补偿；不同视频之间的音量差异，则由自动响度均衡逐步拉近。所有音频都在本机处理，不保存、不上传，也不读取麦克风。

当前源码版本为 **v0.3.0**。安装包版本以 Releases 为准。

## 下载安装

需要 **macOS 14.2 或更新版本、Apple Silicon 芯片**。目前没有 Intel 安装包。

从 [Releases](https://github.com/hugh-zhan9/EvenTone/releases) 下载 `EvenTone-…-macOS-arm64.zip`，解压后打开 `EvenTone.app`。标记为 **Pre-release** 的是预览版。

当前安装包使用临时签名，尚未经过 Apple 公证，macOS 可能阻止打开。每个版本都附带 `SHA256SUMS.txt`，可在下载目录校验文件：

```sh
shasum -a 256 -c SHA256SUMS.txt
```

首次打开时，音频处理默认关闭。播放一段视频，打开 EvenTone 右上角的总开关，按系统提示允许音频录制。如果系统要求退出重开，请从同一个位置重新打开应用。输入、输出电平开始变化，说明已经捕获到音频。

关闭窗口后，应用仍在菜单栏运行；点击波形图标可以再次打开面板。要完全关闭应用，点击面板里的「退出」。

### 没有声音电平，或反复要求授权

先确认有内容正在播放，再到「系统设置 → 隐私与安全性 → 屏幕与系统音频录制」检查 EvenTone 的权限。不同 macOS 版本的设置名称可能略有不同，应用中的「打开系统权限设置」也可以跳转到这里。

「等待音频」只表示还没有收到可显示的音频，不能单凭这个状态判断授权成功。当前使用的临时签名也可能让重新编译后的应用再次要求授权。系统权限由 macOS 管理，应用不能代替系统保存或跳过授权。

## 日常使用

### 切换设备

点击当前设备旁的「切换」，选择要使用的输出设备。勾选项表示当前输出；切换后，EvenTone 会加载该设备保存的补偿，并保留总开关状态。蓝牙设备需要先在 macOS 中连接。

每个设备的补偿范围是 **−12～+12 dB**。系统音量键仍然控制系统音量，EvenTone 不修改硬件音量，也只会在你选择切换设备时修改系统默认输出。

### 引导校准：比较一次，以后自动应用

1. 把当前设备的音量调到舒服的水平，点击「引导校准」。这副设备将作为参考。
2. 暂停其他播放，保持系统音量不变。选择要匹配的设备，戴好参考耳机，点击「试听参考设备」。
3. 戴好另一副设备，点击「试听匹配设备」。两次播放的是同一段 **6 秒**参考声。
4. 根据听感点击「偏小，再响一点」或「偏大，再轻一点」。应用会调整补偿并重新试听，也可以随时点击「重听参考」。
5. 听起来接近后，点击「听起来一致，保存并返回」。以后开启 EvenTone 切换到这副设备时，就会自动应用保存的补偿。

校准页直接在当前面板内打开，按试听进度显示下一步。点击「取消并返回」会回到首页，保留原设置，不关闭窗口、不保存本轮调整，也不会重启正在运行的音频处理。

进入校准后，日常播放的整体音量、设备补偿和自动均衡继续生效；原先关闭的处理仍保持关闭。参考声在内存中生成，单独发送到所选设备，只应用一次补偿。试听时暂停音乐或视频，是为了避免两段声音叠加影响判断。

应用只在点击试听时检查本次设备是否可用，不要求两副设备在进入、选择或保存时同时在线。试听失败会保留本轮调整，连接好后可以直接重试。即使系统默认输出发生变化，校准参考设备也不会跟着变；日常播放则会加载新输出设备的补偿。校准不会修改系统默认输出或硬件音量。

### 手动微调

「设备音量补偿」滑块和「重置」可以独立使用，引导校准后也可以继续调整。

播放一段熟悉的视频并开启 EvenTone，先把整体音量调到合适的位置。保持同一片段、系统音量和整体音量，切换耳机后调整补偿，让两副耳机的听感接近。滑块的改动会立即按设备保存，不需要再点保存按钮。

软件无法仅凭数字音频测出耳内真实声压，所以首次匹配仍需要你听一听。改变硬件音量、耳机模式或使用环境后，可能需要重新校准。

### 自动均衡与总开关

自动响度均衡会逐步抬高轻声、降低响声，减少不同内容之间的音量差异。它不会把每个瞬间都变成一样响，以保留内容原有的动态。关闭「自动响度均衡」后，设备补偿和整体音量仍然有效；关闭总开关则停止全部普通音频处理。

### 登录时启动

开启「登录时启动」，应用会在登录 Mac 后自动打开，不会在登录前作为后台服务运行。处理开关恢复上次退出前的状态：之前开启就继续开启，之前关闭就保持关闭。首次使用默认关闭。

如果显示等待系统允许，可通过设置按钮处理；关闭此选项会取消登录启动。应用重新打开、回到前台或打开面板时，会刷新登录项状态。

登录项绑定的是当前应用位置。请保留正在使用的 `EvenTone.app`；从源码构建时，它位于 `dist/EvenTone.app`。移动应用后，请重新检查登录项状态。

## 支持范围与已知限制

- 普通处理面向系统默认输出设备，支持单音频流的单声道或立体声 **Float32（32 位浮点）音频**。多声道、多音频流设备会明确报不支持。
- 指定其他输出设备的应用、独占播放和受保护内容不保证能被处理。系统提示音如果使用独立输出，也可能不经过 EvenTone；应用不会修改这项设置。
- 自动均衡采用短时 **RMS（均方根）**估计，包含静音门控、平滑增益和左右声道联动。它不是符合 EBU R128 广播响度标准的 LUFS（相对数字满刻度的响度单位）测量器。
- 峰值保护把普通处理通路的采样峰值限制在 **−1 dBFS（相对数字满刻度的分贝）**，避免增益造成数字削波。这不是过采样真峰值限幅。
- 切换设备、休眠唤醒时需要重建普通音频通路，可能短暂中断。AirPods 通话模式、蓝牙延迟、音画同步和长时间稳定性仍需实机验证。
- 总开关和其他设置保存在 `local.eventone.app` 的 UserDefaults（macOS 应用偏好设置）中。故障导致总开关关闭时也会保存关闭状态；正常退出只释放资源，不改变保存的开关值。

## 从源码构建

需要 macOS 14.2+、Swift 5.10+ 和 Command Line Tools（命令行开发工具）。项目没有第三方包依赖，构建本地版本不需要付费开发者账号。

```sh
git clone git@github.com:hugh-zhan9/EvenTone.git
cd EvenTone
./scripts/build.sh
open dist/EvenTone.app
```

仓库不包含编译产物。`build.sh` 会完成 release 编译、生成图标、打包并使用本机临时签名（ad-hoc 签名）。重新构建会覆盖 `dist/EvenTone.app`，请先退出正在运行的应用。

`swift build` 可以单独检查编译。运行音频功能时，请使用带 `Info.plist` 的 `.app`，以便系统显示正确的用途说明。

有签名证书时，可以指定签名身份：

```sh
EVENTONE_SIGN_IDENTITY='证书名称' ./scripts/build.sh
```

临时签名不等于 Developer ID 签名或 Apple 公证。不要通过关闭 Gatekeeper（macOS 应用安全检查）绕过系统保护。

### 测试与诊断

目前 **30 项音频与应用逻辑测试通过**。算法测试直接通过 C 语言的数字信号处理模块（DSP）处理合成信号，覆盖响度收敛、峰值、静音、低底噪、声道比例、异常数值、单帧、单声道和缓冲区映射；应用逻辑测试覆盖配置保存、设备切换的确认/超时/错误，以及登录项的注册、取消、待批准和外部状态变化。

```sh
./scripts/test.sh    # 独立测试执行器，无需 XCTest 或完整 Xcode

# 只读诊断，不捕获音频、不修改设备设置
./dist/EvenTone.app/Contents/MacOS/EvenTone --diagnose
```

测试失败会以非零状态退出。测试通过不等于耳机听感已经实测：下次实际登录启动、AirPods 切换、主观匹配和长时间运行仍需验证。已完成的实机检查与未验证范围见 [验证记录](docs/VERIFICATION.md)。

### 自动打包与发布

| 操作 | 结果 |
| --- | --- |
| 推送到 `main` | 测试、打包，发布 `preview-<提交哈希 SHA 前 12 位>` 预览版 |
| 推送 `vX.Y.Z` 标签 | 测试、打包，发布正式版；标签必须与 `Info.plist` 版本一致 |
| 提交拉取请求（PR）或手动运行工作流 | 测试、打包，仅保存 Actions 构建产物 |

安装包通过 GitHub Releases 发布，不使用 GitHub Packages。每个版本包含 ZIP 和 SHA-256 校验清单；Actions 构建产物保留 **14 天**，Releases 附件持续保留。流水线目前只构建 Apple Silicon（arm64）版本，不包含 Intel 构建、Developer ID 签名或公证证书配置。

发布使用仓库自带的 `GITHUB_TOKEN`，无需个人令牌。构建任务只有读取权限，发布任务仅在受支持的推送事件中获得 Releases 写权限。

正式发布前，更新 `Resources/Info.plist` 中的版本号 `CFBundleShortVersionString` 和构建号 `CFBundleVersion`，提交并推送，再为同一提交创建匹配标签。例如版本为 0.3.0 时：

```sh
git tag v0.3.0
git push origin v0.3.0
```

已有标签和 Release 不会自动覆盖。发布前和公开草稿前，流水线都会核对远端标签与构建提交；标签被移动时会拒绝发布。已成功发布的版本再次执行发布任务会报版本已存在。上传失败可能留下草稿，处理前请先检查该草稿与 Actions 日志。

本地验证发布与打包脚本时，先构建 `dist/EvenTone.app`：

```sh
python3 -B -m unittest discover -s Tests/ReleaseTests -v
python3 -B -m unittest discover -s Tests/PackageTests -v
./scripts/package.sh dist/EvenTone.app dist/release 0.3.0
```

需要把构建产物放到其他目录时，可设置 `EVENTONE_DIST_DIR`，避免覆盖正在使用的应用。

### 项目结构

界面与状态管理使用 SwiftUI，普通音频通路使用 Core Audio process tap（进程音频捕获）和私有 aggregate device（聚合设备），DSP 使用 C11 和无锁原子配置。应用不安装驱动，也没有网络服务。

```text
Sources/EvenTone/       界面、设置、设备切换与音频通路
Sources/AudioDSP/       实时音频处理（C11）
Tests/EvenToneTests/    独立测试执行器与回归测试
Resources/Info.plist    应用信息、版本号与权限说明
scripts/               构建、测试、打包与发布脚本
docs/                  设计与实机验证记录
```

实现依据见 [概要设计](docs/loopx/design/2026-09-16-mvp/概要设计.md)、[实现合同](docs/loopx/design/2026-09-16-mvp/需求设计文档.md) 和 [Apple 官方示例](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)。Core Audio 细节同时参考本机 macOS SDK（开发工具包）头文件。
